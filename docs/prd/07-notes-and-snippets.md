# 7. Notes and snippets

Where the things that aren't tasks or events end up: lecture notes, pasted
articles, links, code, addresses.

## One Notes page

A single page in the navigation. Not grouped by course or anything else:
just everything, **newest first**, like flipping back through a notebook.

- Each row shows the title, the first line or two, and when it was added.
- **Snippets** sit in the same list with a small mark. A link shows its
  page title and site ("Recursion explained · youtube.com").
- A course tag is shown on the row if the item has one, but it doesn't
  change the order.
- A small switch at the top: **All | Notes | Snippets**.

## Finding things again

The main job for snippets. A search box at the top of the page filters the
list as I type, matching titles and text. (Searching across everything in
the app, tasks and events too, is section 9.)

## Opening a note

- Title and body, both editable in place. The body is plain text with
  simple Markdown (headings, lists, links, code), shown formatted.
- Where it came from, with a link back to the original drop or file.
- Delete with undo, like tasks.

## Adding

- Mostly through the inbox: Claude decides when something is a note or
  snippet (section 4).
- A **new note** button on the page for writing one directly.

## Not doing (for now)

- Folders, tags or grouping.
- Pinning or favorites.
- Rich text editing (bold buttons, images inside notes).
